# tools

Standalone paper-export scripts. Deliberately self-contained (no `app_core` imports, pure stdlib) so they can run independently of the Flask app. Both write into `paper_exports/FORGE-VI/`.

- `forge_vi_paper_metrics_exporter.py` — `FORGE-VI_LevelC_Workflow_Checks.{json,csv}`, `Operational_Metrics.csv`, `Reconstruction_Metrics.csv`, `Comparison_Metrics.csv`, `Paper_Tables.tex`, `Field_Source_Map.csv`. Triggered by the "Generate Level C Workflow Metrics" button (Paper Evidence dashboard) and, since 2026-07-21, automatically at the end of every Level C job.
- `forge_vi_cpr_edge_matrix_exporter.py` — `FORGE-VI_LevelC_CPR_Edge_Matrix.{json,csv}`, `CPR_Aggregate.json`, `CPR_Interpretation.md`, `CPR_Diagnostics.json`. Triggered by "Generate CPR Edge Matrix" and, since 2026-07-21, automatically at the end of every Level C job.

## Change log

### 2026-07-21
- **Both scripts only ever saw whatever `CASE-*` directories were still physically on disk** (`EVIDENCE_STORE.glob("CASE-*")`) — the per-repetition cleanup (`foc_experimentation/retention_service.py`) deletes a case's heavy directory shortly after that repetition's own analysis finishes, keeping only a lightweight bundle under each campaign's `level_B/EXEC-000N/retained_case_lightweight_bundle/<case_id>/`. Confirmed live: `forge_vi_paper_metrics_exporter.py` found only **1** case on an install that had just run a 3-repetition Level C campaign (should have found ~31 across its full history). **Fixed** in both: case discovery now also recovers cases from their preserved lightweight bundle when the live directory is gone (mirrors the identical fix already applied to `app_core/infrastructure/forge_vi_dashboard/endpoints.py._case_dirs()` — duplicated rather than imported, since these scripts are deliberately self-contained). `forge_vi_cpr_edge_matrix_exporter.py` additionally checks each EXEC directory's own `retained_case_lightweight_bundle/` first (it already knows exactly which bundle is its own) before falling back to a fragile positional-index guess against the live case list.
- **`forge_vi_cpr_edge_matrix_exporter.py` had a hardcoded `CAMPAIGN_ID = "CMP-20260705-214036-62E8"`** — a single fixed campaign from July 5, meaning every run of this script, regardless of when, always processed that same stale campaign. Confirmed as the reason `CPR_Aggregate.json`/`CPR_Diagnostics.json`/`CPR_Edge_Matrix.*`/`CPR_Interpretation.md` had been frozen since 2026-07-07. **Fixed**: added an optional `--campaign-id` CLI override, defaulting to the most recently updated Level B campaign (`_default_campaign_id()`) — same "most relevant = latest" default already used in `forge_vi_dashboard` and the other exporter script. `forge_vi_paper_metrics_exporter.py` had a related, smaller version of the same pattern (an unused `level_b_cmp` enrichment fallback required `execution_count >= 6`, silently matching nothing for any normal-sized campaign) — replaced with the same "most recently updated" heuristic.
- Verified live: `forge_vi_paper_metrics_exporter.py` now finds 31 real cases (was 1); `forge_vi_cpr_edge_matrix_exporter.py` now correctly targets `CMP-20260720-230112-DFA1` (the actual latest campaign) with real, varying per-execution CPR values (0.625/0.625/0.625/0.625/0.5/0.625), not a single stale mashup.
