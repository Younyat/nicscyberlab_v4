# static

Frontend: `index.html` (single-page app shell + most inline JS, including the global job/preservation status indicators) plus `js/*.js` per-feature modules (e.g. `foc_repetition_manager.js` for Level A/B repetition UI).

## Key parameters / gotchas

- **`getBrowserDfirMode()`/`setBrowserDfirModeOn()` (`foc_repetition_manager.js`) read/write a pure `localStorage` flag (`nics_dfir_auto`)** — there is no server-side DFIR mode state. The Level B launch dialog forces this to `"on"` before sending `dfir_mode_before`/`dfir_mode_after` to the backend, regardless of what the user had set. Don't assume this flag reflects anything real about the lab.
- **The global status indicators (`#dfirPreservationIndicator`, `#lcLiveIndicator`) poll their backend endpoint every 2.5-3s** and (for `dfirPreservationIndicator`) cache the last-seen summary in `localStorage` for continuity across page loads. Any cached summary needs an expiry — see below — otherwise it renders forever regardless of current backend state.
- **`state.activeJobId` (localStorage key `nics-foc-experimentation-active-job`) is a SEPARATE "currently tracked job" mechanism** from `#lcLiveIndicator`, still used by `renderJob()`/`pollJob()` to update the `#job-panel` grid in the Repetition Manager view. It's repointed by every call to `trackJob()` (Level B repetitions launch, Level A report generation, comparability jobs, paper evidence jobs — see `foc_repetition_manager.js`, `foc_paper_evidence.js`, `foc_reconstruction_comparability.js`), so `#job-panel` can jump to an unrelated job's progress if the user triggers a second action while a long batch is still running. It no longer has a floating global toast (removed 2026-07-16, see below) — it only updates `#job-panel` now, which is only visible when that view is open.
- **`hydrateExperimentationJob` (`foc_repetition_manager.js`) blends 3 different progress sources** (`lifecycle.progress_percent`, `analysis.progress_percent`, raw `payload.progress_percent`) into one displayed number when a nested lifecycle/analysis sub-phase is active, feeding `#job-panel` above. `mapLifecycleProgressToWrapper`/`mapAnalysisProgressToLifecycle` both clamp into a `[74, 88]` band representing "we're in the nested phase slice of the outer bar" — any fallback used in that branch must also stay in that band, never the raw unclamped payload value (see fix below).
